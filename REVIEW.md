# REVIEW.md

List every defect found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Startup (missing) | No indexes created. Without a unique index on `emp_code` and `(emp_code, date)`, uniqueness relies on check-then-insert (races). No sort/filter indexes → COLLSCAN on 100k docs. | Two concurrent `POST /employees` with same `emp_code` → both return 201. `GET /attendance` on 100k rows is slow. | Added `lifespan` event that idempotently creates: unique index on `employees.emp_code`, unique compound on `attendance_logs.(emp_code, date)`, sort index `(date DESC, emp_code ASC)`, and `(department, emp_code)`. |
| 2 | `health()` L72-74 | Always returns `{"status": "ok"}` without pinging MongoDB. Contract requires 503 when DB is unreachable. | Stop MongoDB → `GET /health` still returns 200. | Added `client.admin.command("ping")` in a try/except; raises `HTTPException(503)` on failure. |
| 3 | `compute_late_minutes()` L36-37 | Two bugs: **(a)** Threshold check `minutes > 10` uses integer-divided minutes, not total seconds. Punch at 09:40:01 (601 s): `int(601/60)=10`, `10 > 10` is False → returns 0, should be 10. **(b)** `punch_in.replace(hour=h, minute=m)` applies IST shift time onto the punch_in datetime which may be UTC from PyMongo — wrong timezone comparison. | **(a)** `POST /punch-in` at 09:40:01 IST for 09:30 shift → `late_minutes=0` instead of 10. **(b)** Run server in UTC → all late calculations wrong. | Check `total_seconds > 600` (grace threshold), then `floor(total_seconds / 60)`. | 4 | `compute_work_hours()` L41 | Python `round()` uses banker's rounding (round-half-to-even). R4 requires half-up rounding. | 29250 seconds → 8.125 hours. `round(8.125, 2)` = 8.12 (even digit); half-up = 8.13. | `Decimal(str(value)).quantize(Decimal("0.01"), ROUND_HALF_UP)`. |
| 5 | `compute_overtime()` L44-47 | Three bugs: **(a)** Returns any positive overtime value; R3 requires ≥ 30 min threshold, else 0. **(b)** Overnight shifts: `shift_end` placed on `date_str` date, but should be +1 day (e.g. 22:00→06:00: end should be 06:00 next day, not same day). **(c)** Creates an IST-aware `end` but `punch_out` from PyMongo is naive UTC → timezone mismatch in subtraction. | **(a)** 5 min overtime → returns 5 not 0. **(b)** Overnight shift gets ~16 hours of spurious overtime. **(c)** `TypeError` or silently wrong result. | **(a)** `return minutes if minutes >= 30 else 0`. **(b)** Add 1 day when `shift_end ≤ shift_start`. **(c)** Ensure punch_out is tz-aware before comparison. |
| 6 | `create_employee()` L79-80 | Race condition: `find_one` then `insert_one` is not atomic. Insert directly; catch `DuplicateKeyError` from the unique index → 409. |
| 7 | `create_employee()` L82, L85 | `datetime.now()` returns a naive datetime in the server's local timezone (not UTC). The response returns this raw datetime object instead of integer epoch milliseconds as the contract requires. | `created_at` appears as a datetime string like `"2026-07-06T10:00:00"` in the response, not an integer. Clock interpretation varies by server timezone. | `datetime.now(timezone.utc)` for UTC storage; `format_employee()` converts to epoch ms via `dt_to_epoch_ms()`. |
| 8 | `list_employees()` L93-95 | Four bugs: **(a)** `skip = page * page_size` — page 1 skips the entire first page (should be `(page-1)*page_size`). **(b)** `count_documents({})` ignores the department filter. **(c)** No `.sort("emp_code")` — contract requires ascending order. **(d)** `created_at` returned as BSON datetime, not epoch ms. | **(a)** Page 1 is empty. **(b)** Department filter shows total for all departments. **(c)** Order is undefined. **(d)** Type mismatch in response. | **(a)** `(page - 1) * page_size`. **(b)** `count_documents(q)`. **(c)** `.sort("emp_code", ASCENDING)`. **(d)** `format_employee()`. | 9 | `punch_in()` L101 | No check for unknown employee. If `emp_code` doesn't exist, `find_one` returns `None`, and `emp["shift_start"]` raises `TypeError` → unhandled 500. | 10 | `punch_in()` L104-105 | Race condition: check-then-insert on `(emp_code, date)`. Same pattern as defect #6. Two concurrent punch-ins for the same employee and date can both succeed. | Fire two simultaneous `POST /attendance/punch-in` for same employee → both return 201, two records stored. | Rely on the unique compound index `(emp_code, date)`; catch `DuplicateKeyError` → 409. | 11 | `punch_in()` L102-103 | Three bugs: **(a)** `datetime.fromtimestamp(ms/1000)` returns a naive datetime in the server's local timezone, not UTC. **(b)** `ts.date()` computes the calendar date in local time, not IST — wrong near midnight boundaries. **(c)** No overnight shift date logic: R1 says a punch before `shift_end` for overnight shifts belongs to the previous day. | **(a,b)** Server running in UTC: a punch at 00:15 IST (18:45 UTC previous day) → date is the previous UTC day, not the correct IST day. **(c)** Overnight 22:00-06:00 shift, punch at 05:00 IST → date should be previous day. | `epoch_ms_to_dt()` gives UTC-aware datetime. | 12 | `PunchInIn` model L63-66 | **(a)** `status: str = "PRESENT"` accepts any string — "ABSENT", "LEAVE", "FOO" all pass. ## Examined and decided NOT a defect

- **String comparison for YYYY-MM-DD date ranges** (`$gte` / `$lte` in the attendance query): lexicographic ordering matches chronological ordering for this date format. Correct.
- **`IST = timezone(timedelta(hours=5, minutes=30))`**: Correctly defines UTC+05:30.
- **`load_dotenv()` without `override=True`**: By default `load_dotenv` does *not* override existing environment variables, so real env vars take priority. Correct per the contract.
- **Storing dates as YYYY-MM-DD strings and instants as BSON datetimes**: Matches the data model described in `DATA_MODEL.md`.
